# NOTES — стан роботи над прототипом

Ці нотатки для нової сесії, яка не бачила попередніх розмов. Тут — контекст,
ухвалені рішення та наступні кроки. Структуру коду не переказую — вона видима з файлу.

## Що це і де воно

Основний артефакт роботи — **`subscription-details-prototype.html`** у корені.
Це **клікабельний low-fidelity wireframe** порталу ThingsBoard License Portal:
сторінка деталей підписки + флоу «Manage add-ons». Один self-contained файл
(inline CSS + vanilla JS), решта репозиторію (Vite/React-скелет у `src/`) —
окрема історія, до прототипу відношення не має.

Є ще старий `subscription-details-wireframe.html` — це вихідний драфт-референс,
з якого починали. Його не чіпаємо, він лишається як історія.

## Жорсткі константи прототипу (не порушувати)

- **Один self-contained HTML**: inline CSS + vanilla JS, без фреймворків,
  без зовнішніх запитів, **без localStorage/sessionStorage** (стан лише в JS-змінних).
- **Тільки монохром** — чорний/білий/сірі. Жодних брендових/акцентних кольорів
  (зелений з референсів ThingsBoard свідомо ігноруємо). Стан передаємо вагою,
  рамками, заливкою сірого — не кольором.
- Wireframe-фіделіті: структура/інтеракції важливіші за візуал.
- Плейсхолдери чесні: де значення невідоме — `$?`.
- Спільна висота кнопок через CSS-змінну `--btnH` (зараз 31px).
- Клавіатурна доступність + видимі hover/focus стани.
- **Комітимо тільки коли користувачка явно попросить.** Кожну ітерацію вона
  спершу переглядає. Мова спілкування — українська.

## Як перевіряти зміни

Файл лежить на Google Drive, тому у вбудованому браузері (`mcp__Claude_Browser__*`)
він відкривається як **static snapshot**. Наслідки, які треба памʼятати:
- `preview_start`/`navigate` на `file:///.../subscription-details-prototype.html`
  (шлях з `%20` замість пробілів).
- Після редагування — **`navigate` заново** (не покладатись на HMR).
- `location.reload()` іноді віддає stale-DOM; надійніший — повторний `navigate`.
- **`javascript_tool` виконується в ізольованому світі**: бачить спільний DOM,
  але НЕ бачить page-window глобалів (напр. `window.openModal`, функції з IIFE) —
  тому перевіряй через DOM/класи/`getComputedStyle`, а не через виклик page-функцій.
- Відомий артефакт: `#fsAddons` (повноекранна сторінка) інколи лишається видимою
  після тесту в snapshot; у сорсі на ньому стоїть `hidden` — усе гаразд, просто
  прихуй через JS (`document.querySelector('#fsAddons').hidden=true`) щоб побачити
  сторінку деталей.
- **SVG-пастки, на яких уже наступали**: атрибут `hidden` на `<svg>` не ховає без
  CSS-правила (`.icon[hidden]{display:none}` вже додано); `el.hidden = true` як
  JS-властивість — no-op на SVG-елементах, тому тогли іконок робимо через
  `setAttribute/removeAttribute('hidden')`.
- Після кожної правки — screenshot + `read_console_messages(onlyErrors:true)`
  (має бути чисто).

## Дві поверхні «Manage add-ons» (важливо не плутати)

Прототип свідомо містить **два варіанти** одного флоу, перемикаються ран-тайм:

1. **Modal** (`#addonsOverlay`, контролер `AM` у JS) — компактна двокрокова
   модалка з фіксованою висотою (`--? `: `min(790px,92vh)`) і скролом лише в body.
2. **Full-screen** (`#fsAddons`, контролер `AMF`) — **окрема сторінка** (не модалка):
   mini-заголовок + close, title-row з «Change plan →», дві колонки (зліва
   обʼєднаний блок Plan+Add-ons зі скролом, справа sticky «Calculation summary»
   з кнопкою «Review →» під ним).

Перемикач: **gear-кнопка** внизу праворуч (`#gearBtn`) → панель «Prototype settings»
з радіо Modal / Full-screen. Дефолт — Modal. Стан у JS-змінній `addonsStyle`
(без persist). Кнопка «Manage add-ons» у секції Plan & Add-ons відкриває обраний
варіант.

**Дані обох варіантів — план Prototype** (base $39/mo, Devices 50 фіксовано,
Production incl 1, Dev 0, AI 2×1M; add-ons Edge +$7, Trendz +$12; плейсхолдер
per-unit: production +$29/mo, development +$15/mo, AI-блок +$5/mo за 1M).
Проратація зміни рахується як `delta × 16/31` (16 з 31 днів циклу до 2026-08-30).
Логіка розрахунку — у контролерах AM/AMF (`changes()`, `render()`, `render2()`).

### Свідома розбіжність між варіантами
Full-screen нещодавно переосмислили як **окрему сторінку**, тож він розходиться з
modal і це ОК: у full-screen «Plan» замість «Capacity», «Calculation summary»
замість «Billing impact», обʼєднаний блок, картки без рамок (стек), менші
item-сабхеди (13px), Change plan → у subhead, Devices як disabled-текстфілд.
Модалка лишається у своєму компактному вигляді. **Контент-зміни (тексти, ціни,
чекбокси) зазвичай дублюємо в обидва; layout-зміни full-screen — лише туди.**
Класи `.am-*` спільні для обох варіантів — коли треба змінити лише full-screen,
скоупимо через `.fs-screen .am-...`, інакше зачепиш модалку.

## Ключові рішення (і чому)

- **Прибрали таби на сторінці деталей** → весь контент одним вертикальним скролом,
  блоки розділені дівайдером. Порядок: Plan & Add-ons → Billing & Invoices →
  Production instances → Audit logs. (Користувачка хотіла менше навігації, більше
  «сторінкового» відчуття.)
- **Приховали бокову + топ навігацію** (`.sidebar,.topbar{display:none}`, `.app`
  → одна колонка) — «щоб не відволікала». Стилі збережені, легко повернути.
- **Контент 3/4 ширини**, притиснутий ліворуч (`.sheet{width:75%}`).
- **Change plan** тримаємо в subhead full-screen і в subhead модалки (не на картці
  Devices) — на картці Devices лише «fixed by … Plan» з lock-іконкою. Це кілька
  разів «гуляло» — фінально узгоджено: **Change plan у subhead**.
- **Заголовки блоків vs item-сабхеди**: блокові — uppercase; item-сабхеди зробили
  дрібнішими, щоб не конкурували.
- **Іконки біля цін**: coin для звичайних цін, lock для «fixed by …» —
  через CSS `::before` з data-URI (тому колір захардкоджений сірий `#6b6b6b`,
  бо currentColor у background не працює).
- Проратацію/«due today» лишаємо явним рядком; «Due today» = прораційна частина
  зміни, не повний новий тотал.

  замовчуванням, фіксована висота.

## Відкрите / наступні кроки

- **Немає підвішеного TODO від користувачки** — чекаємо наступний запит. Робота
  йде короткими ітераціями «зміни → рев'ю → (за проханням) коміт».
- Можливе питання на потім: чи зводити modal і full-screen до спільного контенту
  (зараз свідомо розійшлися), чи лишати як дві окремі патерн-демо для порівняння.
- Дрібний борг: у JS лишились «мертві», але нешкідливі шматки після видалення
  табів (напр. `selectTab`/`$$('.tab')` тепер працюють над порожнім набором) —
  не критично, можна прибрати при нагоді.
- Якщо знову зʼявиться скарга «кнопки різної висоти» — перевір реально: усі
  header-кнопки вже 31px (`--btnH`); візуальна різниця зазвичай через filled vs
  outlined стиль, а не висоту.
