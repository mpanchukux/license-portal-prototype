Design system

Back to the portal

Every token and component the portal is built from, rendered from the same styles.css the pages load — nothing here is a copy or a screenshot. Change a rule and this page changes with the product. Each specimen is labelled with the class you write to get it.

Tokens

The variables on :root. Swatches and sizes are read from the live stylesheet at load, so they cannot drift from the values the product uses.

Colour

Two layers, and a component may only read the second. Primitives (--c-green-600, --c-red-600, --c-grey-600) are raw values named by hue and step, and nothing uses them directly. Meanings (--status-ok, --status-alert, --status-off) are what a rule reads. Two layers because “what is this colour” and “what is it for” are different questions, and because a brand restating its green is then one edit.

This is the monochrome rule ending, in stages (2026-09-25). The constraint read: state is carried by weight, border and fill — never by hue, with three named exceptions on the selling surface. Status and version are the first elements coloured on purpose. Everything else is still grey, and stays grey until it is asked for.

Colour is never the only carrier, and that is what keeps this accessible. Every coloured mark ships with two other signals: a differently shaped glyph (a check, a cross, an exclamation — three outlines, not one in three tints) and, where there is room, the word. Remove the colour entirely and every one of them still reads. A tone-only carrier — the phone card’s status stripe — is still an open debt, not a precedent.

--accent, --tick and --page-bg are still literals and do not go through the primitive layer. They predate it and they sit on the selling surface, where a value change is a visible change; folding them in is a pass of its own.

Type scale

Nine levels across two tiers plus the key, a 14px floor, and weight that grows with size (700 only on display and h1). The compact tier is what ≤600px substitutes for h1, h2 and body — the phone is not the desktop scale shrunk, it is its own three sizes.

display currently has no user. It was written for numbers that carry a page, briefly styled the landing page’s Welcome, and lost that when the landing head was reduced to one heading — the H1 there takes h1 like every other page. The level is kept and documented rather than deleted, because a scale with a hole in it is harder to read than one with an unused top step; but nothing in the product renders it today.

Exceptions, all of them. Every other hardcoded size in the stylesheet is one of these, and nothing else is allowed to join the list without moving into the table above.
· Glyph sizing — gone. This entry used to excuse 22, 20, 19, 18, 16, 15 and 13px boxes for buttons whose label was a character — a kebab, a close, a plus, a back arrow. Every one of them is an icon from the sprite now, on one of three sizes, so there is nothing left to except. See Icons.

· Two mono stacks — .mono uses the raw system stack, while --font-mono (Ubuntu Mono) is used only by .nl-keybox code and this page’s own chrome. The key therefore renders in two different faces depending on where you meet it.

Icons

One closed set, and nothing else draws. Every icon is a <symbol> in assets/icons.svg, generated from @tabler/icons 3.48.0 by tools/build-icons.py. No inline <path>, no emoji, no text glyph, no second library — and tools/check-icons.py fails the pass if one appears.

How an icon is placed

The same four lines everywhere. The path is relative, because the site has to work from a subfolder.

<svg class="ic" aria-hidden="true">
  <use href="assets/icons.svg#ti-device-desktop"></use>
</svg>

In markup built by JS there is a helper that writes exactly that: icon('device-desktop', { size:20, cls:'gb-ic', label:'…' }).

Three sizes .ic / .ic-20 / .ic-24

16 is the base and needs no class. There is no fourth size: before this the stylesheet carried thirty bespoke icon boxes between 13 and 26px, most of them a pixel or two apart and none of them a decision.

Colour

An icon is the colour of the text it sits in. The symbol paints with currentColor and no rule anywhere may paint one — set color on the thing that contains it.

Labelling

An icon that carries meaning on its own gets role="img" and a name. An icon beside a text label is aria-hidden, because announcing it reads the same thing twice.

The whole set

Everything available, with the name to ask for it by. An icon the prototype needs that is not here is added to the sprite from Tabler under its official Tabler name and reported in the pass that adds it. If no Tabler icon fits, the pass stops and asks — nothing is drawn by hand.

Buttons

THE FIFTH AXIS ARRIVED ON 2026-09-28: surface — what the button is standing on. The model had no answer for it, and twice in September a secondary had to be repainted by hand (on the ink banner, and on the landing page’s pale swap box); the note each time said a third case and this becomes an axis. The third case was the licence header going to the gradient: on a coloured ground --surface-quiet neither reads as a control nor stays the same colour as the pools drift under it. On white a secondary is grey; on the gradient it is white. The class goes on the CONTAINER, not the button — .on-tint on any block with a coloured ground — a mesh, or the flat lavender the licence header took on 09-28. What a button stands on is a fact about the place; a caller passing surface:'mesh' would be repeating something the surface already knows, and would be wrong the day the surface changes — which it was, one pass later, when that header stopped being a mesh. Primary is untouched: ink on a pale tint is the most contrast in the product.

One component, five axes (button() in shared.js). Variant · size · content · state · surface, plus tone. A flat list of named buttons would need a new name for every combination (primaryLargeIconDisabled); axes do not. Every cell below is rendered by the component — nothing on this page is drawn by hand, so the matrix cannot disagree with the product.

The matrix variants down, states across

The last column is the icon-only form, and it is there so the width difference is visible: an icon-only button is not the label form narrowed, it is sized from the icon plus its own padding. At md a ghost or text one is 54×40 and a secondary one is 62×40, because secondary carries a 24px glyph and the box is measured from what is in it — a rounded rectangle lying down, not a square. menu is the one that goes the other way: 38×40, slightly taller than wide, because a kebab is a glyph three dots across. That contrast is the point — you can tell a menu trigger from an action at the end of a row without reading either.

An icon-only button carries a GREY glyph (2026-09-28). --mid at rest, --ink on hover and press — the treatment menu has always had, now on secondary too. Copy and kebab sit side by side at the end of every list row on the same quiet fill; drawing one in ink and one in grey said there was a difference between them, and there is not. A secondary WITH a label keeps ink. There the glyph is decoration beside a word and the word has to carry the contrast.

It used to be a square (40×40, and menu a narrow 28), which is the lazy reading of “icon-only”: the box came from the band rather than from what is in it. Width is padding now, not a number — a 20px or 24px icon makes a wider button by itself, and nothing has to remember a second figure when an icon changes size.

Radius: 24px on everything with a label, a stadium on everything without one. 999px is not a guess — the browser clamps it to half the shorter side, so the ends are true semicircles at every height. Note what 24 does at md: the box is 40 tall, so the browser clamps 24 to 20 and a labelled md button renders as a full pill. Only lg (48) shows 24 as an actual corner. If a visible corner rather than a pill was the intent, the number has to be under 20.

Sizes three, and the third has one user by design

sm 26 — actions inside an ink banner, where the band would out-shout the banner. md 40 — --btnH, everything standing in a control row. lg 48 — the page’s own primary beside its h1. lg was 56 and is now 48. 56 next to a 40px toolbar is a jump; 48 is a 1.2 step and reads as bigger without shouting. One call site is the right number for a hero — a page has one primary action.

The mobile touch rule lives in the component, once. Below 600px sm and md both resolve to 44. This replaced three contextual overrides — .pubacts .btn{height:36px}, .pagetitlerow .btn{min-height:44px} and #couponOverlay .paymodal-f .btn{height:48px} — three answers to one question, in three places, with three numbers. No call site says anything about size now.

Tone default · destructive

An axis, not a variant, because we need a destructive primary (the confirm in the cancel dialog) and a destructive text item (Delete in a kebab). As a variant each of those would need its own name. The variant decides the shape; the tone decides the colour, from --status-alert.

This fixes an inversion. .btn.ter carried the comment “destructive” and rendered quieter than an ordinary button — underlined grey text — so in the cancel dialog the destructive action looked least like a button of anything on screen. The usability session caught the same inversion.

States without colour

Hover and pressed are two different surfaces, not two opacities of one. On a filled button hover goes flat black and pressed adds an inset well at the top edge — a recess, which flat black cannot be. On a quiet filled button (secondary, menu) hover and pressed are the next two steps of that fill's own ramp — --surface-quiet-hover then --surface-quiet-press. On a transparent one (text, ghost) hover takes --hover and pressed takes --sel, two greys the product already uses for exactly this pair.

Secondary is a FILL, not an outline (2026-09-25). It was white with a --line border; it is --surface-quiet (#F4F5F6) with the border turned transparent rather than removed — .btn declares a 1px transparent border for every variant, so a button keeps the same box whichever one it wears. Drop it here and a secondary icon button comes out 2px narrower than a primary beside it. menu takes the same fill: the reference shows that trigger as a filled grey shape, and in a table row a bare kebab beside a filled copy button read as two kinds of control doing the same kind of job. What stays menu's own is the width.

Every icon button in a list row is the quiet filled one. The licences and invoices tables both use it, so a row's actions read the same wherever you are.

Pressed is new work. :active appeared zero times in 4,600 lines of stylesheet before this.

Focus is a ring and it is not hover. :focus-visible only — a mouse click does not raise it.

Disabled does not respond, and that was a bug. The old .btn:hover{background:#000} was unguarded, so a disabled primary still went black under the cursor and kept cursor:pointer; there was no global .btn[disabled] rule at all — the fade was written separately inside four containers and nowhere else. Every hover and active rule is now guarded.

Busy is the sixth state, and it is not disabled. Disabled means you cannot do this; busy means this is happening. It reserves its own width with the hidden label rather than freezing one with an inline style, keeps the accessible name, sets aria-busy, and uses aria-disabled rather than the disabled attribute so focus is not lost mid-action. Restoring is the default — the purchase confirm opts out explicitly, because the surface behind it is replaced. The 600ms refresh spin is this state at a shorter duration, not a second mechanism.

THE SPINNER IS INSERTED AT RUNTIME (fixed 2026-09-28), and until then it was not. button() emits it for a button built busy; a button that BECOMES busy only ever got the class — which hides the label and the icon and put nothing in their place. Refresh therefore went blank for 600ms and read as “the press did nothing”, which is how it was reported. And what the class hides is now > *:not(.btn-spin), not .btn-txt,.btn-ic: those two are what the BUILDER emits, and the Refresh buttons are written in HTML with a bare <svg class="ic"> — so the glyph survived and the spinner was drawn on top of it. A busy button hides its content; naming the builder's own classes made that true only for what the builder built.

Not allowed, on purpose

The component refuses these rather than leaving them undocumented:

· menu with a label. The kebab is the whole of that variant; a labelled one is a secondary button with a chevron, which already exists.
· menu at lg. It is a trigger inside a row, never a page action.
· busy together with disabled. “You cannot do this” and “this is happening” are different statements and one button cannot make both. Busy wins.

What the model cannot say: which ground it stands on. On the ink banner a primary is ink-on-ink and vanishes, so the banner re-paints the component’s surfaces for its dark ground (.gbanner .btn--primary). The classes are still the component’s; only the palette is local. If a second dark surface appears this becomes a fifth axis (surface), not a second copy of that block.

Inputs

Form controls share the control height and the same focus treatment: the border goes to ink.

They read --btn-r as of 2026-09-28 (by request). Fields were the last 40px controls still on a 6px corner: the search box, the view switcher, the period control and every toolbar button moved to the shared radius on 09-27 and the FORM fields did not, so one dialog held two corner languages at the same height. The padding grew with the corner, and that is not decoration — at 40px tall a 24px radius clamps to a pill, so the widest point of the arc is exactly at the vertical middle and text set at 10px sits ON the curve. 16px clears it; the search box has recorded the same arithmetic since its own radius changed.

THE SELECT’S CHEVRON IS OURS (2026-09-28), and the pass before this one got it wrong: it set padding-right:38px believing that would move the native arrow. It does not. Measured afterwards — the text moved 38px in and the glyph stayed hard against the control’s right edge, because the UA draws it in its own space and no padding reaches it. The only way to place it is appearance:none and draw one. And the one we draw comes from the sprite, inside a .selwrap. A CSS background-image would have been one line and is precisely what the icon rule forbids — a path inlined outside assets/icons.svg; referencing the sprite as a background does not work either, because a <symbol> is not a renderable fragment. The wrapper costs ten call sites and keeps the closed set closed. --sel-gutter is the select’s own left padding, read twice, so the glyph cannot drift from the distance the text sits at on the other side.

A textarea is NOT a pill: multi-line, so there is no height for 24 to clamp against and the corner would come out as a real quarter-circle on a box of text. 12px — rounder than it was, still a rectangle. A menu is a container, not a control: 10px, like every card and popover.

SPACING: 18px, and it is ONE number (2026-09-28, by request). .field’s bottom margin, and .field2’s row gap AND its own bottom margin. The report was “no space at all between the inputs on Billing & Payment”, and it had two causes: the grid’s row gap was 12px, so the next row’s LABEL sat closer to the control above it than to its own input — and the grid had no bottom margin whatsoever, so a two-up row followed by anything sat at a gap of exactly 0 (measured: Company / Billing email ended at y=260 and Phone began at 260). The second was the larger half.

THE CARD FIELD’S EXPIRY AND CVC ARE BLOCKS INSIDE IT (2026-09-28, by request), not columns of it. They were bare inputs with a full-height border-left:1px between them — a hairline at the same weight and colour as the field’s own stroke, two pixels from the arc that stroke draws, so the eye read three strokes and could not tell which one was the field. A fill separates without adding a line: two quiet chips at 28px inside a 40px field, and the divider goes, because the gap between two filled shapes IS the divider.

RED, AS OF 2026-09-28, and this page carried the promissory note for it. Every error treatment in the product used to say the same thing: “the brief asked for the error colour; the prototype is monochrome by hard rule, so this goes to ink instead — one token if the rule is revisited.” The rule was revisited on 09-25, status and version went coloured, and an error in ink was then the last thing using WEIGHT to say what the palette now had a colour for. It is --status-alert, not a new token — the red that already means act now on Blocked and Past due. A second red for errors would be two answers to one question. 5.09:1 on white, so it passes as text.

Colour is still not the only carrier. The border thickens AND turns, the label turns with it, and the message is words. Printed in grey, every failed field still reads. The message says what is wrong, not that something is — “Use MM / YY” can be acted on; “invalid” cannot. .help is hidden while an error shows: two lines under one field, one of them now wrong, is worse than either alone.

The message is a CAPTION, and the field pays for it out of its own margin (2026-09-28, by request, from a reference). It was 14px bold — the same size as the value in the field above it and heavier — so a form with three bad fields grew by three full lines and everything below it moved while the reader was fixing it. It is --t-caption-fs (13/1.35) now, and .field.err drops its 14px bottom margin, so a field that fails grows by about 4px rather than by a line. --t-caption is a sixth step in the type scale, added for this one job: use it for something that sits UNDER something else, and for nothing else.

No glyph on the message. It carried a drawn (!) circle and that mark was removed: it repeats what the message already says, while costing a hanging indent that pushed a two-line error out of line with everything else under the field. The fault is signalled three times already — border, label, and the line itself.

The rule that goes with it: a primary action is never left disabled with nothing said. Either it is enabled and answers on submit — painting every failure at once and moving focus to the first — or it is disabled with the reason visible beside it. The purchase wizard’s billing step and the update-card modal both take the first form, and a .formerr summary sits with the button naming how many fields are waiting. Fields answer on blur, and typing again withdraws the answer.

Status chips

A licence’s status is a coloured word now (statusMark) — the word alone, in the colour of its state. The chips below still read by weight and border — attention states take the ink fill, quiet states stay outlined. Buttons no longer do: secondary is a fill (see Buttons), so an outline on this page means a chip, not a control.

The licence status mark

The word, in its own colour, and nothing else. --status-ok for Active, --status-off for Canceled, --status-alert for Blocked. No icon.

This reverses yesterday, and the note it replaces is worth keeping visible. That version put the colour on a 20px glyph and kept the word in --ink, arguing that a coloured word “would carry the meaning a second time and would fail the moment it sat on a coloured ground”. Neither half survives: there is no glyph left to carry it, and this cell never sits on a coloured ground.

Colour is now the only VISUAL carrier here, and the word is what saves it. Active / Canceled / Blocked are three different strings, not one label in three tints — a reader who sees no colour at all still reads the status. That is the line that must not be crossed: the moment two statuses share a word and differ only in hue, this cell fails.

All three statuses clear AA as text. Computed on white: --status-off 7.81:1, --status-alert 5.09:1, --status-ok 4.56:1 against a 4.5 floor at 14px regular.

--status-ok was #009A4F and failed, at 3.66:1, and the record of how is worth more than the fix. It passed while it was a glyph — 1.4.11 asks 3:1 of a non-text mark — so the value never changed, the floor did, the moment the colour moved onto a 14px word. The glyph coming back on 2026-09-27 did not fix it either, and that is the easy mistake: the mark and the word are measured by different rules, and only the mark was ever in question. Changed on 2026-09-28 to #008846 — hue and saturation held, lightness alone darkened, the first value that clears the floor. One line, in the primitive.

Blocked is inferred. The reference covered Active and Canceled; Blocked is the third value this cell has always had, and leaving it an ink pill between two icon marks would be one column speaking two languages. It takes the alert colour because it is the one status that means act now.

Canceled, one L. The reference writes “Cancelled”. Every other surface — the menu item, the cancel dialog, the activity copy — spells it with one, and a status disagreeing with the dialog that sets it is worse than a spelling preference.

The glyph came back on 2026-09-27, and it is what makes the promise at the top of this page true for this cell. Between 2026-09-25 and then the column carried the word alone beside a colour — the note written at the time said so in as many words — which is one carrier, not two. Three states, three outlines: circle-check, circle-x, alert-triangle-filled. Remove the colour and the column still reads.

The version mark versionMark

One line, one type treatment, and a mark only when something is wrong. The latest 3.9.4 line is gone, the green tick is gone, and in the list across N instances is gone with them. What is left is the number, and an alert beside it when the number is not the latest.

Silence is the up-to-date state. A tick marked the ordinary case, so a column of ticks said “normal” nineteen times to make one exclamation stand out — and the exclamation stands out better with nothing beside it. The number the running one is compared against lives in the alert’s tooltip: “The latest product version is 3.9.4.” Only the alert has one; there is nothing to ask about a licence that is already current.

The digits are one weight in both states. The behind number used to be 500, which gave one kind of value two type treatments in one column. The alert is the difference; the digits are just digits.

Table

The licence table, rendered by the same builders the Licenses page calls (headHtml() / rowHtml()) — header, sortable column, a row with its actions, and the pager.

A table is a framed object (2026-09-25): the head is a filled --surface-quiet band and the whole table sits inside its own hairline with a 10px radius. Home, Licenses, Invoices and the flat Instances list are all this one look. A row under the cursor takes --row-hover — literally the blue Home fades into, so the highlight belongs to the product rather than being a grey borrowed from the button ramp. It is transient: nothing is selected, the pointer is simply there.

The specimen carries .listframe, because that is what the frame is scoped to. Without it this page would keep showing the table as it looked before — which is the failure mode this page exists to prevent.

The frame comes off below 600px — every row is already its own card there, so an outer frame would be a box holding boxes. A collapsed group has no outline at all: the outline is what says “these rows belong to this heading”, and with nothing showing there is nothing to enclose.

This page said the frame came off in the GROUPED Instances view as well, and that stopped being true on 2026-09-27. The argument then was “the groups are the framed objects”, and it held only while a group’s own outline was the only thing separating it from the next. The headings are banded now, so the frame is back doing the one job it does on every other list — saying where the table ends — and the groups are inset 12px from it (2026-09-28) so two hairlines are not left touching.

A group heading’s hover was invisible on every other group until 2026-09-28, and the reason is worth keeping: the alternating fill is written with an ID in its selector and the hover was not, so the banding out-scored it. Both resolve to --row-hover now, the same blue every other list answers with.

The frame is four bands, in this order

Toolbar · column header · rows · pagination footer. One block, one surface, one hairline round the outside. The first two stick — the toolbar (.stickybar) under the app bar, the column row (.stickyhead) directly beneath it — and rows pass under both for the whole length of the list.

The footer is NOT sticky, and that is a decision. The top of the frame is pinned already; pinning the bottom as well leaves a strip of list between two fixed bands — on a 13″ laptop, about six rows of window.

The footer shows only what is true (2026-09-28). The count always shows: a list that will not say how long it is makes the reader scroll to find out. Anatomy

What it is about · what happened · what changed, from and to · who did it · the time. A reason or an amount sits inside the sentence, never only behind the expander — a failure that hides its cause behind a click is a failure you have to go and ask about.

The day is a separator, the time trails the sentence (2026-09-28). The entry used to open with the full Sep 13, 2026, 07:12; the date is a row of its own on the axis above the run of entries that share it, and the entry keeps only 07:12, after the sentence. Printing the date on every row would print it fifty times under a separator that already says it once. And the entry is not self-sufficient because of that: on its own it says 07:12 with no day, which is why every surface goes through activityList and only this page does not.

A CHANGED VALUE IS DRAWN AS THE CHANGE (2026-09-28, from a reference): the old value struck through and quiet, an arrow, the new one in a .pill. It was old → new — two words at two weights, which asks the reader to work out which is current from the boldness. The pill is the only enclosed thing in the row, so the eye lands on it; the struck value is there to be checked rather than read. The plain pill, not a coloured one — the reference fills it pale blue, and that would be a sixth pill in a scale whose five all mean something, for a job the plain one (“this is a named value”) already covers.

One chip per entry, always the same thing. In the account-wide feed the entity sits in a chip (.fi-chip) — the licence label, the instance label, the user’s email, the invoice number. Everything else is plain, values included. That gives a scannable column of names, and a chip says “this is a named thing” rather than “this matters more”. It was bold until 2026-09-25, and weight was the problem: .em inside sentences and the attention labels in rows were already spending it — three jobs, one voice. Two entries have no chip at all, and that is correct: a password change and an invite link have no named subject but the account itself. It is LIGHT BLUE as of 2026-09-28 (by request): --c-blue-50 with --accent on it, not --sel. That grey is the selected-nav wash — it means “this row is picked” everywhere else it appears, which is not what a named entity inside a sentence is saying. The chip and the disc on the rail are now the same pair, so blue in this feed means one thing in both places it appears. 12.1:1.

In a licence’s own tab the entity is dropped, not chipped again — the page already says which licence you are in. Same event, two renderings; that is what the scope argument is for. In the map it is one template: the bracketed segment ([ on {entity}]) is what the licence scope removes. For an instance event the bracket holds the licence and the instance keeps the chip — what the page already states is what goes.

Voice. Past tense, no auxiliary: Plan changed from Startup to Business, never Plan was changed. One sentence, ending in a period. No “successfully”, no adjectives. Dates inside a sentence use the product’s one format, Sep 13, 2026 — the entry’s own timestamp is split between the day heading and the time column, but a date the copy mentions is written out in full. Eleven of the twenty-nine reach true active voice; the rest stand as participles with the auxiliary dropped, because English has no agentless active for “user removed”. Active: plan changed, capacity changed, updates end, payment failed, payment succeeded, instance checked in, check failed, credit rose, payment method changed to, session ended, password changed. One entry — the folded run — has no finite verb at all. The boundary is a judgement, not a measurement: “session ended” is counted active because it reads intransitively. It is a compromise, not a choice, and it is the one rule on this page the copy does not fully meet.

Who did it is in the sentence, as {by}, and the template says where — several sentences carry a trailing clause after an em-dash, and appending the actor would produce “active until Sep 05, 2026 by Mariia”. A machine event has no actor at all, rather than saying “System”: check-ins, expiries, automatic charges and the credit a downgrade returns simply end. The absence of a name is what says nobody did it.

No HTML in a string, ever. The copy says what happened; the component decides what is emphasised. That is what lets search match the sentence directly — before this, search read textContent, which included the hidden expander, so a uuid that appeared only inside the raw payload matched all 298 rows.

The expander is not a raw record. It shows named field · from → to rows, and only for the types that have something to show; a type with no detail gets no button. A grouped run expands to the entries it folded.

1 · Sentence and actor the default

Somebody did something. One sentence, the actor at the end, the time at the right. No panel, nothing to expand — most of the map is this.

2 · With a detail panel rec.detail

The sentence carries the headline change; the panel carries what the sentence left out, as named field · from → to rows. It must never repeat the sentence — a Plan: Startup → Business row under “Plan changed from Startup to Business” is the same fact printed twice.

3 · No actor a machine event

Check-ins, expiries, automatic charges and the credit a downgrade returns. The sentence simply ends rather than saying “System”: the absence of a name is what says nobody did it. An automatic charge is its own type, not a paid-invoice entry with the name left off — “charged automatically” is a fact the reader wants, and an empty actor can only say that we do not know who.

4 · A grouped run instance.checks_grouped

Check-ins are derived, not stored — the licence reports hourly, so a nineteen-instance account would otherwise write hundreds of rows a day. An unbroken run of successful checks for the same instance becomes one entry carrying the count and both ends of the run.

It does not expand, and nothing in the feed does. It used to open to the entries it folded, and that list said nothing the summary had not: the checks are hourly and the summary prints the count and both ends, so every line was derivable and each carried the same two words. It is removed, not hidden behind a click.

A failure never joins a run, even between two successes: it is the entry the reader is scanning for, and it names its cause in the sentence.

5 · A gap between two runs the structure is the message

A run covers consecutive checks. When an expected check never arrives, the run ends and a new one starts after the hole — so two groups with nothing between them are how the feed says a check is missing. Below: a run ending at 18:10 and the next beginning at 20:10, with no failure row between them. The 19:10 check never came.

This is the one thing the summary cannot say. “4 successful checks, 08:57 to 11:57” is equally true whether or not 10:57 happened, and no expander would have fixed that — the missing check is not in the group to be expanded to. Only the break between two groups carries it.

The cadence is recorded, not guessed. The gap is measured against CHECKIN_INTERVAL_H — the interval the product states — and a delta below 1.5× it is treated as the same check arriving early or late. Jitter is absorbed; only room for a whole missed slot breaks a run.
